# Data and provenance

## Public schema

| Column | Type | Meaning |
|---|---|---|
| `event_id` | string | Stable incident identifier |
| `incident_date` | UTC datetime | Incident observation date |
| `loss_usd` | non-negative float | Reported loss in USD |
| `incident_type` | string | Vulnerability or attack class |
| `target_type` | string | Protocol/product category |
| `chain` | string | One chain or a pipe-separated chain set |
| `protocol_id` | string | Normalized protocol identifier |
| `<graph_feature>` | float | Graph-derived value |
| `<graph_feature>_available_at` | UTC datetime | Earliest verified availability time |

`event_id` must be unique. Predictive profiles reject graph values without safe availability
timestamps.

## Sources

The conference research combined Rekt incident reports, DeFiLlama protocol metadata, and SlowMist
verification. Exact links, purposes, and the redistribution decision are recorded in
[`data/provenance.json`](../data/provenance.json).

The repository follows a fail-closed policy: raw third-party records are not committed until their
current terms explicitly permit redistribution. A researcher supplies their own export and is
responsible for complying with the source terms.

## Included sample

`data/sample/incidents.csv` is generated by `scripts/generate_demo_data.py`. It is synthetic, carries
no claims about real protocols or incidents, and exists solely for tests, onboarding, and CI.

## Normalization

The builder accepts:

- a Rekt-style JSON object containing `data.rekts`; or
- a CSV already following the public schema.

It normalizes identifiers and dates, removes records missing ID/date/loss, deduplicates by event ID,
and derives only one graph feature automatically: the count of strictly earlier incidents for the
same protocol. Structural graph facts require a separate timestamped source.
